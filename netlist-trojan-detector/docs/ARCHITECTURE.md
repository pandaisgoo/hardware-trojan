# 實作架構（依提交程式整理）

行號對應本套件未修改的 `detector.cpp`，不是依舊 PDF 的敘述推定。

| 元件 | 程式位置 | 實際作用 |
|---|---|---|
| `Gate` / `Graph` | 18–29 | 儲存閘型別、名稱、輸入／輸出，及訊號 driver/readers 的索引。 |
| `normalize_gate_type` | 40–51 | 閘型別轉小寫，將部分名稱歸類；例如 XOR/XNOR 歸入同一類。 |
| `build_graph` | 53–71 | 依閘的輸入／輸出填入 `gate_map`、`wire_driver`、`wire_readers`。 |
| `tokenize` | 73–105 | 切開指定標點，過濾空白與註解。 |
| `extract_wire` / `parse_netlist` | 107–256 | 處理訊號名稱、具名或位置式接腳、部分 output 與 assign 語法。 |
| BFS 輔助函式 | 280–342 | 追蹤訊號的邏輯來源／讀取者，部分追蹤會略過 buf/not。 |
| 特徵偵測 | 348–1469 | 十組規則；使用區域大小、DFF 關係、閘型別比例、扇出等條件。 |
| 平行搜尋 | 1492–1516 | `std::async(std::launch::async,...)` 同時啟動十組搜尋，再等待結果。 |
| 結果選擇 | 1525–1559 | 依 0 到 9 的固定優先順序選第一組 found 結果，不做所有結果聯集。 |
| 輸出 | 1565–1569 | 候選清單空則輸出 NO_TROJAN，否則輸出 TROJANED 與閘名。 |

## 描述時需避免的誤差

- 程式有 `normalize_gate_type()`，但沒有 PDF 所述的 `normalize()` 匯流排展平函式；不應直接寫成已完成 `n1[5] → n1_5` 的轉換。
- 此版本未實作 PDF 所述 `CONSTANT_` 命名的虛擬常數節點機制。應描述本版本的實際程式，而不是將舊報告所有設計敘述搬入 README。
- `is_isomorphic_trojan_x` 函式主要是區域探索及特徵門檻，不是對一般輸入保證正確的精確子圖同構演算法。
- 「十組規則」不等於「十種木馬全部成功偵測」。目前沒有依真實模板類型整理的測試結果，不推測每組規則的個別成功率。
- 使用 hash map 的索引查詢，與列舉一條線的全部 readers 是不同工作；不能將後者整體宣稱為 O(1)。

以上為整理時的靜態對照，未修改或自動修正提交程式。
