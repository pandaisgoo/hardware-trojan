# AES-128 硬體木馬模擬與時序分析

以 Verilog 保存 AES-128 的正常版本與兩組受控硬體木馬範例，研究條件觸發、狀態紀錄與輸出時序的關係。本實作限於隔離的模擬與硬體安全研究，不是部署於實際產品的攻擊工具。

## 目前內容

| 目錄 | 角色 | 檔案數 |
|---|---|---:|
| `AES/` | 正常加密包裝與核心 | 5 |
| `sample_HT/` | 計數與輸入條件觸發的實驗版本 | 5 |
| `bonus/` | 連續輸入匹配與狀態控制的實驗版本 | 5 |

每組均包含 `AES_top.v`、`aes_128.v`、`expand_key_128.v`、`round.v`、`table.v`。檔案保持上傳內容，不更換模組或參數名稱。

這三個目錄重複定義相同的模組名稱，因此它們是分開使用的配置，不要將三組 RTL 同時加入同一個編譯清單。

## 驗證狀態

原先的 PDF 有模擬波形與時序說明；但這次 ZIP **沒有** `AES_top_tb.v`、Makefile 或原始 FSDB/VCD 波形檔。本整理環境也沒有原使用的 ncverilog/Verdi；本次沒有重新執行 RTL 模擬。

因此，這是保留原始程式的專案整理版，不是 clone 後即可重現全部實驗的完成包。不能把舊 PDF 的圖片當作本次重跑結果。

## 要補齊的驗證材料

請從原本可執行的專案補回三種配置相應的 testbench、Makefile／模擬命令、檔案編譯清單及模擬紀錄。先確保版本對應，再重新核對原先的波形與結論。

測試與文件應區分：正常輸出、觸發前後的時序、狀態更新，以及未觸發時的行為。此處列的是待整理的驗證範圍，不宣稱目前都有自動化測試。
